Security and data handling

How FTZ Control protects your zone records. Last updated 29 October 2026.

Your data stays yours

  • Records live in a dedicated PostgreSQL database. They are encrypted at rest by the database host and encrypted in transit: every connection to the app is HTTPS, and the app talks to the database over TLS.
  • The app connects to the database with a restricted account. It cannot create or drop tables, and it cannot edit or delete the audit log or the inventory ledger. The database's public API is switched off for these tables (row level security with no public access).
  • Passwords are stored only as salted PBKDF2-SHA256 hashes. Sign-in tokens, reset tokens and API keys are stored only as SHA-256 hashes: a database copy cannot be used to sign in.

Sign-in protection

  • Optional two-factor sign-in with any authenticator app, plus one-time recovery codes. Administrators can reset a lost device.
  • Repeated wrong passwords or codes are blocked for 15 minutes. Passwords must be at least 10 characters and cannot be common or contain the user name.
  • Sessions expire after 12 hours, cookies are HttpOnly, Secure and SameSite, and changing a password signs the person out everywhere.
  • Roles: Administrator, User, and a read-only Auditor for customs auditors and advisers who need to look but not change.

A record that stands up to an audit

  • Every change is written to an append-only audit log. The audit log and the stock ledger are hash-chained (each row carries a SHA-256 fingerprint of the one before), so an edit or a removed row is detected by the integrity check.
  • The database itself refuses negative inventory and refuses to change or delete history, even if the application had a bug.
  • Supporting documents are fingerprinted when stored and re-checked on every download. They are never deleted; a wrong file is voided with a reason and stays on record. Every upload, download and void is logged.

Application security

  • Strict content security policy, HSTS, no framing, no content sniffing, and cross-site request protection on every change.
  • The application code is served only to signed-in users. Uploaded files are always downloaded, never displayed in the browser, and are checked against their declared type.
  • ERP and WMS connections use revocable API keys that can reach only the endpoints they need.

Backups and availability

  • The database host takes daily backups with point-in-time recovery. Administrators can also download a full copy of the data at any time.
  • A health check monitors the service and the database.

What FTZ Control does not do

  • It prepares the e214, FZ and in-bond data that your team or broker files through ACE. It does not transmit filings to U.S. Customs and Border Protection.
  • It does not replace your own compliance review of what is filed.

Reporting a security concern

Email the contact address your administrator gave you, or the address shown on the front page, with the details. Please do not include customer data in the message.
